### 设计：`VirtualSeeker`

我们将创建一个新的 `VirtualSeeker` 结构体，它将作为所有分片文件的“智能代理”。

#### `VirtualSeeker` 的工作原理

1. **初始化** ：在创建时，它解析 KVI，获取所有子分片的元数据（文件名、大小），并计算出总大小。它**不会**打开任何文件。
2. **`Seek(offset, whence)`** ：

* 当收到一个 `Seek` 请求时，它会根据 `offset` 和 `whence` 计算出目标的全局位置。
* 遍历子分片元数据，确定这个全局位置落在哪个子分片文件上。
* 计算出在该子分片文件内部的 **局部偏移量** 。
* 如果当前打开的不是目标文件，它会关闭当前文件，然后打开目标文件。
* 在目标文件上执行 `Seek` 到局部偏移量。
* 更新内部状态（当前分片索引、全局位置）。

1. **`Read(p []byte)`** ：

* 从当前打开的文件中读取数据。
* 如果当前文件读到了末尾，但还有数据未读完，它会自动关闭当前文件，打开下一个分片文件，并继续读取。
* 这个过程对上层调用者是透明的。


### BigEndian vs LittleEndian 的区别

在性能方面，对于现代的通用 CPU（x86, x64, ARM），两者几乎没有区别。CPU 可以同样高效地处理它们。选择哪一种，更多是关于 **历史传统、协议标准和互操作性** 。

* **BigEndian (大端序)** ：网络协议（TCP/IP）和许多文件格式（如 JPEG）使用，被认为是“网络字节序”。数据的高位字节在前，符合人类的书写习惯。
* **LittleEndian (小端序)** ：Intel x86/x64 架构使用。数据的低位字节在前，在某些计算上更方便。

**最关键的原则是：加密和解密双方必须使用完全相同的约定。**

1. **分片容器头部** （VirtualSeeker处理）：

* 主分片：80字节 + KVI长度
* 子分片：72字节

1. **加密流头部** （SeekableCTRStream处理）：

* 魔法数字：19字节
* IV：16字节
* 总共：35字节


### `SO_REUSEADDR` 与端口共享

在许多操作系统（包括 Windows）中，默认情况下，多个程序可以监听同一个 IP 和端口组合，这通常通过 `SO_REUSEADDR` 套接字选项实现。

1. **“幽灵”服务的行为** ：那个占用 1999 端口的程序，可能是一个比较“宽松”的服务器。它监听端口，但没有声明“这个端口是我的，谁也别想再用”（即没有设置 `SO_EXCLUSIVEADDRUSE` 选项）。
2. **Go 的 `net.Listen`** ：Go 的 `net.Listen` 在底层默认也会设置 `SO_REUSEADDR`。这使得它能够在某些情况下，成功绑定到一个已经被非独占方式占用的端口。
3. **内核的调度规则** ：当有两个进程监听同一个 IP 和端口时，操作系统的网络栈会根据规则来决定将传入的连接交给谁。通常， **第一个启动的进程会“赢得”大部分连接** ，成为事实上的“主要”监听者。

## 🧩 ENCV 容器格式 v2.0

我们设计了一个健壮、可扩展的容器格式，它是所有功能的基石。

### 设计哲学

*   **索引优先**：所有元数据都存储在中央目录，实现快速定位。
*   **分块存储**：数据和元数据分块存储，每块都有独立的 CRC32 校验。
*   **从后向前**：通过读取文件末尾的固定签名来定位中央目录，高效且可靠。

### 容器布局

```
+--------------------------------------------------+
|              ENCV 容器文件                       |
|                                                  |
|  (数据块 1, 数据块 2, ... KVI 块, 签名块)         |
|  +--------------------------------------------+  |
|  |            中央目录                        |  |
|  | - 魔数 "ENCD"                             |  |
|  | - 版本号, 块数量                           |  |
|  | - [块索引表: 类型, 偏移量, 长度]             |  |
|  +--------------------------------------------+  |
|                                                  |
|  +--------------------------------------------+  |
|  |            文件尾签名 (32 bytes)           |  |
|  | - 魔数 "ENCV"                             |  |
|  | - 中央目录偏移量/长度                      |  |
|  | - 全局CRC32校验                            |  |
|  +--------------------------------------------+  |
|                                                  |
+--------------------------------------------------+
```
