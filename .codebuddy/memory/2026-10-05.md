# 2026-10-05

## 1. 真机首测云控热更新（新版安卓 ac5e1c75ede3）

### 真机**已通过**的部分
- **I1 重启自恢复两次验证通过**：后端 00:56 与 01:00 两次重启，设备仍保持 00:48 那次配对
  （`pairedAt` 未变）且 `online:true` ⇒ **没有重新扫码**。这是 I1 的真机闭环。
- 新版二进制认得 `get_device_info`（`goos:android / goarch:arm64 / mobile:true`、
  edge connected:true、searchIndex state=building）⇒ 诊断工具已在真机生效。
- Hub 侧 `bundle/manifest|download|status|push` 端点在真机链路上工作（含 401 鉴权）。

### 真机抓出的**两个真缺陷**（均已修 + 先红后绿）
1. **清单把包名/版本切错**：`web-v0.0.1-test.zip` 按最后一个 `-` 切 ⇒
   name=`web-v0.0.1` version=`test` ⇒ 设备按它拼下载 URL ⇒ 404。
   修：按**第一个** `-` 切（版本号常带连字符，包名一般不含）。
2. **执行端 handler 没接线**：`OnBundleUpdate` 只加进 `peerEdgeHandlers` 与
   `edgeHandlers()` 默认值，**漏了传给 `NewEdge` 的 EdgeOptions** ⇒
   真机 push 得到 `502 + remote error: not_supported`。
   修：`startEdgeLocked` 补上。另加 `peerlink.Edge.Supports(method)`：
   让"接没接线"可断言（否则 `not_supported` 分不清是对端旧还是本端漏接）。

### 环境/操作坑（下次直接避开）
- **Hub 跑在 `ENCV_MOBILE=1`（make dev-mobile）下 ⇒ `config.AppDataDir` 派生成安卓路径**
  （`/data/user/0/com.encvgo.app/files/.encv/<subdir>`）。云侧包仓库因此落在不存在的目录。
  ⇒ 桌面 Hub 要用 `ENCV_BUNDLES_DIR=<真实目录>` 显式覆盖（`AppDataDir` 会优先读该 env）。
- **杀后端进程别只 `pgrep -f exe/encv`**：实测端口上是另一个 pid（`/api/runtime.pid` 才是真的），
  残留进程会让新进程抢不到 2025 而漂移端口 ⇒ 表现成"改了代码没生效"。
  正确做法：kill 后用 `/api/runtime` 核对 pid + started_at。
- 造测试 zip：容器里**没有 `zip` 命令**，用 `python3 -c "import zipfile"` 代劳。

### 未通过（诚实）

  本轮修复只有装机后才能在真机跑通。
- 建议这次构建**同时带上 I3**（`findExecutableBinary` 改 filesDir 优先）⇒
  之后后端与 web 资源都能云控下发，永不再重新构建 APK。

## 2. I3 Go 二进制热更新（已实现，待装机真机验证）

- **Kotlin**（`EncvGoService.findExecutableBinary()`）：`<filesDir>/encv-go` **优先**于 APK 内
  `libencv-go.so`，两道门禁：① `.version` sidecar 存在（说明是云控通道放的）；
  ② `.abi` == `Build.SUPPORTED_ABIS[0]`（架构不匹配 ⇒ CANNOT LINK EXECUTABLE）。
- **失败自动回滚**（关键，不能省）：用热更二进制启动失败 ⇒ `publishFailure` 里把它 rename 成
  `.bad-<ts>`、作废 sidecar、用 APK 内二进制**重试一次**。后端挂了连远程调试都救不回来，
  宁可丢掉这次更新也不能让设备不可用。
- **Go**（`bundle.ApplyFile`）：staging → sha256 + 必含文件校验 → 备份 → **rename 原子覆盖** →
  chmod 755 → 写 `.version`/`.abi`。⚠️ rename 覆盖正在运行的可执行文件是安全的
  （进程继续持有旧 inode）⇒ **新二进制要重启进程才生效**（下次冷启动/服务重启自动生效）。
- 包名 `go-binary`；下发**必须带 ABI**，否则执行端 `rejected: missing_abi`。
- 测试：`internal/bundle/apply_file_test.go` 4 例 + `TestPeerLocalGoBinary_RejectedWhenUnknownOrNoABI`。
  红验：去掉摘要校验 ⇒ ErrChecksumMismatch；去掉备份 ⇒ "换执行体必须留备份"。
- **未验证**：`:app:compileDebugKotlin` 在本环境跑不通 —— JitPack `getActivity:Logcat` 解析失败
  （前置网络问题，与本改动无关；带 `-I scripts/gradle-buildscript-mirrors.gradle` 也只能解 Maven
  Central 的 429，解不了 JitPack）⇒ Kotlin 改动只做了逐行复核。
- 遗留：热更二进制**不会自动触发重启**（靠下次冷启动）。要"下发即生效"需补
  `GoProcessPlugin.restartBackend` 触发路径。

## 3. I4 主应用 SPA 热更新（已实现，待装机真机验证）

- **关键机制（别照抄 PreviewAssetsActivity）**：`bridge.setServerBasePath(path)` →
  Capacitor `WebViewLocalServer.hostFiles(path)` ⇒ 把**任意应用私有目录**托管在**同一个
  https://localhost 源**下。origin 不变 ⇒ CORS / baseUrl.ts 判定 / 混合内容全不变，
  插件桥（GoProcess / BarcodeScanner / Filesystem…）照旧。
  ⚠️ 反例：`webView.loadUrl("http://127.0.0.1:<port>/web/")` 会换 origin ⇒ **插件全部失效**
  （PreviewAssetsActivity 能用独立 WebView 只因为那一页不需要插件）。
- **落地**：`MainActivity.applyHotWebBundleIfPresent()`；目录 `<filesDir>/.encv/web-bundle`
  需同时有 index.html + version.json 才切换；有 `.disabled` 标记则跳过（退路）。
- **可观测**：`get_device_info` 增加 `webBundle.{installed,version}` ⇒ 云控下发后可**远程确认**
  生效版本（判定与 Kotlin 一致，缺 index.html 即算未安装）。
- **产包**：`scripts/build-web-bundle.sh [version] [--no-build]` ⇒ `web-<ver>.zip` + `.sha256`
  （dist 内容放 zip 根，base 保持 `/`）。容器里**没有 zip 命令**，脚本用 python3 zipfile。
- **顺带修的真缺陷**：清单按**字典序**选最新版 ⇒ `v0.0.9` 压过 `v0.0.10`、
  `v0.0.1-test` 压过 `v0.0.1-smoketest` ⇒ 云控可能下发**旧包**。改为语义版本比较 `versionNewer`。
- 测试：`TestDiagGetDeviceInfo_WebBundleInstalled` + `TestVersionNewer`(10 例) +
  `TestPeerlinkBundle_Manifest_LatestBySemver`，均先红后绿。
- **未验证**：Kotlin 改动在本环境无法编译（JitPack 不可达）；热更后需重启 APP 才切换。
