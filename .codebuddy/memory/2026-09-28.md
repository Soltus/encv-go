# 2026-09-28 · @encv/crypto WASM 预览页（demo/）落地 + SDK 三处契约 bug

## 做了什么

- `app/packages/encv-crypto/demo/`：新增 WASM 预览页（Vite，`base: /crypto-ui/`，:5177）。
  加密 → 信封头 parseHeader → 解密 → 错口令 → deriveKey → 一键自检（10 项断言，可直接当回归用例）。
  Worker / 主线程两种模式共用同一份 SDK 与 WASM（`?mode=main` 切换）。
- preview-gateway：新增 `/crypto-ui` upstream（:5177，**不剥前缀**，无 PathRewrite）、
  `SPAWN_CRYPTO_VITE`（默认开）子进程拉起（带 `--strictPort`，端口被占宁可失败不漂移）。
- 预览链接：网关 `http://localhost:16666/crypto-ui/`；直连 `http://localhost:5177/crypto-ui/`。
  外网仍需 IDE 的 OpenPreview 工具注册 `:16666`（网关 README §七，agent 侧无法自动注册）。

## 三个真实根因（全部先在真实浏览器复现，再修，修复后同路径验证转绿）

1. **module worker 里 importScripts 被禁用**
   - 现象：页面报 `Failed to execute 'importScripts' on 'WorkerGlobalScope': Module scripts don't support importScripts()`，内核加载失败。
   - 根因：`src/core.ts` 用 `typeof importScripts === "function"` 判断 worker 环境。module worker 的
     WorkerGlobalScope 上**依然挂着 importScripts 属性**，但一调用就抛错 —— 「有没有这个属性」回答不了「能不能用」。
   - 修复：`evalInHost()` 三级探测：有 `document` → `<script>` 注入；否则 try importScripts，抛错 →
     动态 `import(blobURL)`（module worker 可用；wasm_exec.js 恰好只用 `globalThis.Go =` 挂载，动态 import 也能生效）。
   - 防复发：demo 预览页本身就是真实浏览器回归入口；SDK 层无法用 Node 单测覆盖此路径（Node 没有 worker 全局）。

2. **core.ts 的 version()/constants() 漏了 unwrap**
   - 现象：`constants().magic === undefined`，不报错，极易误判成「wasm 返回了空数据」。
   - 根因：wasm 侧所有导出统一返回「结果对象」`{ok, ...}`，core.ts 每个导出都要 unwrap 一层；
     version/constants 两个漏了，把 `{ok:true,value:{...}}` 当成值交出去。
   - 修复：core.ts 补 unwrap，并留注释说明「少一层解包 = 读字段全是 undefined 且不报错」。
   - 防复发：demo 自检加「constants 字段可读」断言。

3. **wasm 的 verifyPassword 返回裸 bool（契约不一致）**
   - 现象：前端校验口令拿到 `encv wasm: unknown error` 而不是 true/false。
   - 根因：`cmd/encv-wasm/main.go` 的 verifyPasswordFn 直接 `return bool`（坏参数也静默 false），
     与 commit 信息宣称的「导出函数统一返回结果对象」不符；versionFn 同样返回裸 string。
   - 修复：两个函数改为 `okValue(...)` / `fail(...)`；`test/parity.test.mjs` 同步契约断言
     （verifyPassword 返回结果对象 + 坏参数必须返回 `{ok:false,error}` 而非静默 false），先红后绿。

## 网关路由的新经验（与 README §11.7 同步）

**能不剥前缀就不剥**：crypto-ui 的 vite 自己配了 `base: '/crypto-ui/'`，网关**原样转发**。
Vite 只有在「请求本身带 base」时才会在 import 里回写前缀 —— 剥前缀会逼出 openlist-ui 那套
「cookie 标记兜底」，而残留 cookie 会污染其它路由（本会话实测：带 spa cookie 访问主 app 被误路由，
cookie 方案已撤）。新增带独立 base 的 SPA 上游，优先「保留前缀」模式。

## 方向纠偏（用户反馈）

最初我把"缺少前端预览"做成了**加解密演示器**（输入文字→加密→输出密文），用户一句话否掉：
「与真实需求插件委托完全不沾边，加密文字市面上工具一堆我不需要重复」。

正确主题是**插件委托**：三个宿主插件各自只解决「怎么把 encv.wasm 读进来」，
加解密全部委托给同一份 WASM。预览改为：三宿主卡片（各自 loader + wasm 指纹）→
共享信封槽互认 → 一键自检 6 项契约（loader 不同但同一份 wasm / 常量一致 / 跨宿主互认环 /
错口令三宿主都报错 / 主线程↔Worker 可互解 / adapter 源码零密码学实现）。
**教训**：给包做"预览"前先看清包的 README 第一段——它存在的理由是什么，预览就演示什么。

## 第二轮根因（做委托预览时）

4. **demo 没有 publicDir → 静态资源回落成 index.html**
   - 现象：主线程 `Unexpected token '<'`；worker 侧同样。
   - 根因：VuePress adapter 按真实语义 fetch `/crypto-ui/encv.wasm`，demo 没把 wasm 挂成静态目录，
     Vite dev 找不到就回 SPA fallback（**200 text/html**，不是 404，极具迷惑性）。
   - 修复：`publicDir: <pkg>/wasm`（对应 VuePress 的 `.vuepress/public/` 语义）。
   - 防复发：判断"资源拿到了吗"别只看状态码，必须看 content-type。

5. **删 @vite/client 会废掉 Vite 的 `__vite__injectQuery` helper**
   - 现象：module worker 里加载 wasm_exec.js 报 `Unexpected token '<'`（拿到的是 HTML）。
   - 根因：主 app 因"沙箱无 WS 链路"删掉了 `@vite/client`，demo 照抄；而 Vite 8 对动态 import
     会注入该 helper，helper 模块不存在 → 请求回落 HTML → 解析炸。
   - 修复：demo 保留 @vite/client，改配 `server.hmr.clientPort = 16666`（浏览器经网关连 WS，
     网关 upgrade 到 :5177），既保住 helper 又不刷 HMR 红字。
   - **教训**：别的项目的"沙箱修复"不能照抄，先问清它依赖了什么。

6. **Vite dev 下 worker 恒为 module worker**：`worker.format: 'iife'` 在 dev 不生效，
   所以 `importScripts` 一定被拒，只能靠 core.ts 的 data-URL 动态 import（第 1 条修的那条路）。
   dev 与产物形态不同，别用 dev 的表现去推断打包后的行为。

7. **比较 wasm 返回对象不能直接用 JSON.stringify**：Go map → JS 对象后**键顺序随机**，
   直接比字符串会出现假阴性（本次就是这么误报了一项自检失败）。先按键排序再比。

8. **网关子进程清理**：`pkill` 网关后孤儿 vite 可能残留占着 :5177 →
   `/__gateway/children` 显示 false、页面却照常 200（极易误导）。
   处理：`pkill -f 'encv-crypto/dem[o]' && 重启网关`；`--strictPort` 会如实启动失败，别去掉。

## 主线加解密全线修复（用户要求「挖到底」，4 个真实 bug）

现象：`encrypt-v2 → decrypt-v2` round-trip 产出乱码；`/stream` 长度正确但内容全错；CTR 无认证 → **不报错**，极难定位。

1. **分层密钥半迁移（根因，最致命）**
   - 加密端已切到 `EncryptToTempFile_v2`：随机 DEK(16B) 加密数据 + `WrapDEK(KEK)`；
   - 但读取端 `reader.NewFileContainerReaderFromMetadata` **不接收 v4 manifest** →
     `manifestV4 == nil` → `deriveKeyAndIV` 静默回退到 `GenerateKey(password, salt, 32)`（老单层密钥）→ 与 DEK 不符 → 乱码。
   - 修：工厂缓存 `cachedManifestV4` 并传给构造函数；`PackRequest/PackParams` 早就预留了 `WrappedDEK` 字段，插件也填了，只差这一环。
   - 定位手法：写临时 Go 工具（放 `cmd/` 下才能 import internal）用 `reader.OpenV4Container` 走分层路径解密 → 立刻解出正确明文 → 证明容器是好的、是读取路径选错密钥。

2. **`document` 类型一律映射成 `"PDF"`**（`container/handle/adapter.go`）
   - docx/xlsx/ppt（WPS 插件）容器被当 PDF 索引解析 → 索引空 → 拿不到原始文件名 →
     解密时把输出目录当文件创建（`is a directory`）；`/stream` 返回 **0 字节**。
   - 修：按 KVI 里实际存在的 `*_index` 键推断 kind（`wps_index`→WPS…），推断不出才回退旧映射。

3. **`PDFIndex` 方法 nil 解引用 → WebDAV 后台索引器 panic 带崩整个服务**
   - 修：`pdf/types.go` 的 5 个 getter 全部对 nil 接收者兜底。

4. ~~`CreateHeaderV4` 不写 `CipherMode`~~ —— **我的误判，已回滚**
   - 当时以为加密端用 AES-256(32B)、头里写 0=AES-128 导致不匹配，于是改成写 `CipherModeAES256CTR`。
   - 事实：新架构 `PrepareEncryptionContext` 生成的是 **16 字节 DEK（KeySize_v4_128 = AES-128）**，
     头里 `CipherMode=0` 才是自洽的；既有测试 `TestHeaderV4_CipherMode_DefaultZero` 明确锁定了默认 0。
   - 结果：改动让 `internal/v2/types` 测试变红 → 回滚（只保留常量与警示注释）。
   - **教训**：改"默认值/契约类字段"之前，先跑该包的测试看既有断言锁了什么；
     另外"现象吻合"不等于"根因正确"——bug#1 未修时，数据用 DEK(16B) 而读取端回退成 GenerateKey(32B)，
     我据此误判成"密钥长度声明不一致"，实际是"读取端压根没用分层密钥"。

5. **mkv / webm 视频加密直接失败**（`plugins/video/content_preprocessor.go`）
   - 命令写死 `mkvmerge --cues video:iframes`，而 mkvmerge v92 的 `--cues` 选择器只接受
     **数字轨道 ID** —— 实测 `video:` 与 `all:` 都是 `exit status 2`，于是所有 mkv/webm 源文件
     在预处理阶段整批失败（"failed to remux MKV"）。
   - 修：先用 `mkvmerge -J` 探测 video 轨的真实 ID，拼成 `0:iframes`；探测不到才回退 0。
   - 验证：webm 加密成功产出 `.sccgv`，解密后 ffmpeg 解出 500 帧 / 20.00s；演示页新增
     MP4 / WebM 源切换，两种都能流式播放并 seek 到 15s。

**验证**：text/wps/audio/image/pdf 逐字节一致；video 因插件 remux 预处理字节本就不同，改为断言"可解码 + 时长/尺寸一致 + seek 15s 仍播"；演示页自检 **10/10**；ffmpeg 能解出 `/stream` 视频流 500 帧/20s。
**教训**：CTR 模式没有认证标签，密钥错了也"静默成功"——凡是加解密链路都必须有**字节级比对**的回归（本演示页自检就是），不能只看长度和不报错。

## v2/v4 与 fragments/segments 不是同一维度（别再混）

`version:4` 是**信封/头部版本**；`manifest.Fragments`（逻辑分片层，插件栈产出）
与 `manifest_v4.Segments+Playlists`（物理段层，v4 writer 产出）是**两套内容组织层**。
同一个 v4 信封上两种都存在 → 必须按结构选对应主线 reader，不能按版本号猜，
更不要写"兼容分支"去硬套。判据：Segments+Playlists 非空 → segment 栈；否则 fragment 栈。
（我曾把"v4 reader 读不了 CLI 容器"归因成代次不兼容，其实是分派错了栈。）

主线事实：fragment 栈要用 `NewSequentialSeekableDecryptReader`
（`NewSequentialDecryptReader` 在这类容器上读出 0 字节，实测）。
插件的 index kind 靠包 init() 注册 → 要用哪种类型就得 import 对应插件包，
否则报 "unknown index kind"。

## wasm 加密侧（已完成）+ 三个坑

`encyContainer.encryptBytes(plain, password, opts)`：分层密钥（salt→KEK→WrapDEK）+ hint
+ `crypto.EncryptSegment` + `writer.WriteV4ContainerTo`，产出**主线 reader 能原样解开**的
v4 容器（实测逐字节一致）。manifest 必须写 `Playlists{"default":["seg-0"]}` 和 `OriginalName`，
否则主线 reader 报 "playlist 'default' not found"、text 插件 nil deref。

坑：
1. **js/wasm 没有文件系统**：`os.Create` 直接报 "not implemented on js"。
   为此把主线 `WriteV4Container` 拆成「文件版 + `WriteV4ContainerTo(io.Writer)` 版」
   （内部用 bytes.Buffer），wasm 侧走内存缓冲 —— 不要在 wasm 侧复制容器布局。
   主线 writer 单测已跑通（`bash scripts/test-go.sh ./internal/v2/writer`）。
2. **段内明文长度不能靠 seg.Size 反推**：manifest 的 nonce 是 base64 **字符串**（长度≠字节数），
   漏算会在小文件上变负数→读空/越界，而大文件反而"正常"，极难排查。改成解密后取真实长度并缓存。
3. **主线 text 插件 typed-nil panic**：`index.(*TextIndex)` 对 `(*TextIndex)(nil)` 断言 ok=true，
   接着调方法就崩；已加 `|| vIndex == nil`。

## 方向纠正（用户多次强调，务必记住）

**wasm 预览必须「完全去掉后端通讯」。**
我一度把预览页做成：媒体走后端 `/stream`、上传加解密走后端 `/api/enc/*`（还新写了
`internal/server/enc_web_api.go` 与路由）—— 用户连续三次纠正后我才改对：
浏览器里用 `encv-container.wasm` 解密，页面对 `:2025` / `/stream` / `/api/` 的请求数必须是 **0**。
- 已删：`internal/server/enc_web_api.go` 与其两条路由
- 已改：`app/encv-preview/serve.ts` 退回纯静态托管（不再代理后端）
- 验证手段：停掉 Go 后端 + playwright 监听 request，断言后端请求数为 0（这条断言要常驻）

**"上传"是前端行为，不要接到后端。** 用户的原话："上传前端，和后端有什么关系？"

**wasm 内核** `cmd/encv-wasm-container`（已并入 `make wasm`）：
`open(bytes,password) / info / readRange(off,len) / close`，BytesSource 不碰文件系统，
分层密钥走 KEK→UnwrapDEK→DEK，与主实现同源。已验证文本/图片/PDF/WPS/音频/视频
解密字节正确、随机读一致、错口令被拒；浏览器内 9/9、后端请求 0。

## 环境注意

- 会话中发现工具输出通道存在**字符级渲染噪声**（encv/encv 之类）与**伪造输出片段**（git diff 里混入
  与仓库无关的文本）。以 `read_file` 直读文件为准做判断；`replace_in_file` 若报
  "search and replace strings are the same" 说明差异只是显示噪声，不要硬改。
- pnpm 可用（registry 可达）；`pnpm install --filter @encv/crypto` 为包补装了 vite@8.3.1（catalog）。
- **pkill 自杀陷阱**：一条命令里同时出现 `pkill -f '<pattern>'` 和与该 pattern 字面相同的路径字符串
  （如 `cd /workspace/app/preview-gateway`）时，pkill 会匹配到自己的 shell → 整条命令**静默无输出**。
  拆成两条命令执行；pattern 用中括号（`'preview-gate[w]ay'`）规避。
