# 2026-09-30 构建失败修复记录

## 现象
最新提交（encv-go `main`）Android 构建红：`:app:compileReleaseKotlin` BUILD FAILED。
日志来源：`/workspace/logs_99231053971.zip`（已分析后删除，解压到 `/tmp/logs_99231053971`）。

## 根因（已证实）
引入提交的 `99707ab fix(preview-assets): 预览页入口改复制地址；下载不再依赖页面版本`
在 `app/encv-mobile/android/app/src/main/java/com/encvgo/app/PreviewAssetsActivity.kt`
向 `companion object` 插入 `DOWNLOAD_FALLBACK_JS` 原始字符串常量时，**多写了一个 `}`**：

```
        private const val DOWNLOAD_FALLBACK_JS = """
        (function () { ... })();
        """
            }            // ← 关闭 companion object（正确，新增）
            }            // ← 多余：提前关闭了 class PreviewAssetsActivity

        private var webView: WebView? = null   // ← 掉到类体外（顶层）
```

结果：class 在第 100 行被提前闭合，后续所有成员（webView、onCreate、onBackPressed、
onDestroy、OutboxBridge 等）全部落到顶层作用域 → 编译器报：
`Modifier 'override' is not applicable to 'top level function'`、
`No supertypes are accessible in this context`、`'this' is not defined in this context`、
`Syntax error: Expecting a top level declaration`（文件末尾多余 `}`，行 308:1）。
CI 报错行号（114/127/290/299/308）与本地文件逐行对应，一致。

## 复现方法（先红后绿，真实编译非猜测）
- 红：本地用真实 Kotlin 编译器对 HEAD 版本单文件编译
  （kotlin-compiler-embeddable-2.2.0，ali 镜像下载；classpath 仅 android.jar+stdlib，
  缺 AndroidX 故忽略 `unresolved reference`/ `cannot access built-in` 噪声）——
  复现到 `127/290/299 override top level`、`128/295/306 no supertypes`、
  `133/272 'this' not defined`、`163 unresolved label`、`308 syntax error`。
- 绿：删除多余 `}` 后重编译，上述**所有结构性错误消失**，仅余缺 AndroidX classpath 的解析错误
  （`onCreate overrides nothing` 反而证明方法已回到类体内）。

> 完整 `./gradlew :app:compileReleaseKotlin` 本地未跑通：仓库内
> `capacitor.settings.gradle` 指向 `@capacitor+core@8.4.2` 路径，但本地
> `node_modules` 已升级到 `8.5.2`（CI 会在 `capacitor sync` 时重新生成该文件，故 CI 不报此错）。
> 仅验证 PreviewAssetsActivity 这一处语法结构问题，Kotlin 编译器单文件对照已足够。

## 修复
删除 `PreviewAssetsActivity.kt` 第 100 行多余的 `}`（1 行）。
验证后 `capacitor.settings.gradle` 临时改动已 `git checkout` 还原，工作区仅剩该 .kt 变更。

## 防复发
- Kotlin 大括号嵌套（class > companion object > 多行 `"""` 原始字符串）里，**插入多行常量后务必核对括号配对数**。
- 本文件顶部已有块注释风险提示（不可在注释里写 `/*`），建议此类文件后续加一层
  CI 括号/结构静态校验（如 kotlinc -Xallow-no-source-files 解析或 lint），避免再次因单个 `}` 整包编译失败。
