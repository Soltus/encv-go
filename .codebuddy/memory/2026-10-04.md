## 1. `.codebuddy/skill-registry.json` 的 updatedAt 噪音 —— **源头修好**（不是靠 git hook）

- **现象**：IDE/MCP 每次扫描技能目录就把全部条目的 `updatedAt` 刷成同一时刻，
  而内容指纹 `hash`（= SKILL.md 全文 sha256）一个都没变 ⇒ `git status` 常年挂红。
- **⚠️ 我第一版做错了（用户当场指出）**：写了 `scripts/normalize-skill-registry.py` +
  `.git/hooks/pre-commit` 去"事后归一化"。用户一句"git hooks 不算真正解决方案，源头 MCP 代码
  就在当前项目" ⇒ 正确做法是**改写文件的那行代码**。
  （教训：先问"谁在写"，再谈"怎么消音"；能用源头修的，绝不上 hook / 事后补偿。
   我当初 grep 就走了弯路：codemogger 对这个 .mjs 返回空集，我没换关键字就误判"写方不在仓库内"。）
- **真源头**：`scripts/skill-manager.mjs`（app-dev MCP 用它管理技能），两处硬伤：
  ① `scanAndSync()` 里 `updatedAt: new Date().toISOString()` —— **无条件刷新**，不管 hash 有没有变；
  ② `saveRegistry()` 无条件 `writeFile` —— 内容一字不差也重写一遍，mtime 变了 git 就显示 modified。
- **修复（已落地）**：
  ① `updatedAt`：内容未变（`hash` + `path` + `displayName` + `description` 全同）⇒ **沿用 prev.updatedAt**，
     只有真变了才写当前时间；
  ② `saveRegistry()` 改为**幂等写**：序列化结果与磁盘内容相同就**不落盘**（返回 false），连 mtime 都不动。
- **验证（真实跑 MCP 代码，不是推断）**：`node` 载入 `skill-manager.mjs` 调 `loadRegistry()` + `scanAndSync()`
  ⇒ 扫到 40 个技能，registry 的 **md5 与 mtime 完全不变**（根本没写盘）。
  反向实验：临时改一个 SKILL.md（hash 变）⇒ registry md5 变 + updatedAt 刷新 ✔（真变更没被吞）；
  改回原文后再扫 ⇒ 再刷新一次（合理：内容确实又变了一次）。
- **清理**：`.git/hooks/pre-commit` 已删除（源头修好后它就是多余的"绕"）。
  `scripts/normalize-skill-registry.py` **保留**，但定位降级为：历史遗留一次性清理 + `--check` CI 校验，
  不再是解决方案本身。

## 2. Robolectric 落地：安卓 JVM 单测 36 tests / 0 failures（此前 19 failed）

- **背景**：前一天刚把 gradle 网络修通，`:app:testDebugUnitTest` 才第一次真正跑起来，
  结果是 `EncvGoServiceTest` / `GoProcessPluginTest` 全挂在
  `Method put in org.json.JSONObject not mocked` / `Intent.setAction not mocked`
  （纯 JVM unit test 里 Android framework 只是 stub）。
- **改动**：
  - `gradle/libs.versions.toml`：`robolectric = "4.15.1"` + library 条目。
  - `app/build.gradle.kts`：`testImplementation(libs.robolectric)`；
    `android.testOptions.unitTests.isIncludeAndroidResources = true`；
    两个测试类 `@RunWith(MockitoJUnitRunner::class)` → `@RunWith(RobolectricTestRunner::class)`。
  - `app/src/test/resources/robolectric.properties`：`sdk=35`、
    `robolectric.application=android.app.Application`（避开项目 Application 的 Bugly 等初始化副作用）。
- **🚨 最大的坑（不解决就是下一次"gradle 卡死"）**：Robolectric **运行时自己下载**
  `android-all-instrumented*.jar`（199MB），它**不走 Gradle 依赖解析**（Gradle 侧镜像/重试全用不上），
  默认直连 `repo1.maven.org` ⇒ 本环境恒 **429** ⇒ 7 秒就 `Failed to fetch maven artifact`。
  仅靠 `robolectric.properties` 里的 `dependency.repo.url` **没能救回来**（properties 读了 sdk=35 生效，
  但 fetch 仍失败）。
  **可用解法**：jar 交给 **Gradle** 下载 —— 新增 `val robolectricSdk by configurations.creating`
  依赖 `org.robolectric:android-all-instrumented:15-robolectric-12650502-i7`，
  用 Copy task 落到 `build/robolectric-sdk`，再给 Test task 设
  `systemProperty("robolectric.offline","true")` + `robolectric.dependency.dir=<该目录>`。
  ⇒ CI/他人机器上零手工预置。
- **验证（可复现）**：特意 `mv` 走手工预置到 `~/.m2` 的 jar，再跑 —— Gradle 自动下载到
  `build/robolectric-sdk`（199MB）且 **BUILD SUCCESSFUL**。XML 报告：
  `ApiProxyUrlRouter 9/0`、`EncvGoServiceTest 14/0`、`GoProcessPluginTest 12/0`、`ExampleUnitTest 1/0`
  ⇒ **36 tests / 0 failures**（改前 36 tests / 19 failed）。
