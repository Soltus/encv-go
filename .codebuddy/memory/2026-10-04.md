## 1. `.codebuddy/skill-registry.json` 的 updatedAt 噪音 —— **源头修好**（不是靠 git hook）

- **现象**：IDE/MCP 每次扫描技能目录就把全部条目的 `updatedAt` 刷成同一时刻，
  而内容指纹 `hash`（= SKILL.md 全文 sha256）一个都没变 ⇒ `git status` 常年挂红。
- **⚠️ 我第一版做错了（用户当场指出）**：写了 `scripts/normalize-skill-registry.py` +
  `.git/hooks/pre-commit` 去"事后归一化"。用户一句"git hooks 不算真正解决方案，源头 MCP 代码
  就在当前项目" ⇒ 正确做法是**改写文件的那行代码**。
  （教训：先问"谁在写"，再谈"怎么消音"；能用源头修的，绝不上 hook / 事后补偿。
   我当初 grep 就走了弯路：codemogger 对这个 .mjs 返回空集，我没换关键字就误判"写方不在仓库内"。）
- **真源头**：`scripts/skill-manager.mjs`（app-dev MCP 用它管理技能），两处硬伤：
  ① `scanAndSync()` 里 `updatedAt: new Date().toISOString()` —— **无条件刷新**，不管 hash 有没有变；
  ② `saveRegistry()` 无条件 `writeFile` —— 内容一字不差也重写一遍，mtime 变了 git 就显示 modified。
- **修复（已落地）**：
  ① `updatedAt`：内容未变（`hash` + `path` + `displayName` + `description` 全同）⇒ **沿用 prev.updatedAt**，
     只有真变了才写当前时间；
  ② `saveRegistry()` 改为**幂等写**：序列化结果与磁盘内容相同就**不落盘**（返回 false），连 mtime 都不动。
- **验证（真实跑 MCP 代码，不是推断）**：`node` 载入 `skill-manager.mjs` 调 `loadRegistry()` + `scanAndSync()`
  ⇒ 扫到 40 个技能，registry 的 **md5 与 mtime 完全不变**（根本没写盘）。
  反向实验：临时改一个 SKILL.md（hash 变）⇒ registry md5 变 + updatedAt 刷新 ✔（真变更没被吞）；
  改回原文后再扫 ⇒ 再刷新一次（合理：内容确实又变了一次）。
- **清理**：`.git/hooks/pre-commit` 已删除（源头修好后它就是多余的"绕"）。
  `scripts/normalize-skill-registry.py` **保留**，但定位降级为：历史遗留一次性清理 + `--check` CI 校验，
  不再是解决方案本身。

## 4. 双端互联：手机端无信任提示 + 信任后仍连接失败（两个真因，均已修并验证）

- **复现（真实浏览器，手机视口 390×844 + 桌面视口 1440×900 同时跑）**：
  - 手机端粘贴配对码后：`sasNodeCount=0`、**信任按钮 0 个**、只有 `okMsg="已连接：<裸URL>"`
    ⇒ 桌面端在等 SAS 核对，手机端却什么都不显示（用户反馈"困惑"的来源）。
  - 手机端 `互联状态：连接中…`、桌面端 `/peers` 两个设备 `online:false`。
- **真因 A（问题 1）**：远端 Hub 的 `/api/peerlink/pair` **本来就返回 `sas`**，但
  `pairToRemoteHub()` 只解析 `peerId`/`token`，把 `sas` 丢了；`/edge/pair` 也不带

  `/api/peerlink` 后缀（如 `http://host/api/peerlink`），而 `startEdgeLocked()` 又拼了一次
  `hub + "/api/peerlink"` ⇒ Edge 去连 `/api/peerlink/api/peerlink/ws` ⇒ `websocket: bad handshake`
  ⇒ 手机永远"连接中…"、桌面显示离线 ⇒ 用户视角就是"信任了还是连不上"。
  - 漏网原因：既有测试 `TestPeerlinkEdgeRuntime_PairThenHubQueriesEdge` 传的 hub 是

  - 还有一处放大伤害：`Edge.Start()` 把 `runSession` 的错误**吞掉**（只用于退避），
    `/edge/status` 又不返回失败原因 ⇒ UI 只能用"连接中…"掩盖失败（静默失败）。
- **修复**：
  1. `peerlink_edge_runtime.go`：`pairToRemoteHub` 返回 sas；`/edge/pair` 带 sas；

## 7. 真机回归（装 APK 后）：两个我自己引入的 bug + 一条验证方法论

- **① 真机扫码必失败**：`There is no PermissionCallback method registered for the name: cameraPermissionCallback`
  —— 我把权限回调误标成 `@PluginMethod`，Capacitor 要求 **`@PermissionCallback`**（且方法名必须与
  `requestPermissionForAlias(alias, call, "名字")` 的第三个参数一致）。改注解即可，编译通过后待真机复验。
  **教训**：Capacitor 权限回调与插件方法是两套注解，混用会让权限申请这一步就抛错。
- **② 手机端配对后状态、重进设置页就丢**：旧实现把「已连接 / SAS」只放在组件本地 ref，
  组件一重建就清空（真机反馈"重进设置丢失状态显示"）。改为**从 `/edge/status` 恢复持久区块**
  （"已连接到会合点 X" + "断开连接"）。并补 `usePeerLink.stopEdge()`：
  **手机是 Edge，`/peers` 只有 Hub 才有** ⇒ 手机端不能用 `unpairPeer(peerId)`，必须走 `/edge/stop`
  （这也是"移动端不显示配对设备"的根源：纯 Edge 侧没有 peers 列表，属设计如此，需靠 /edge/status 呈现）。
  验证（真实浏览器）：`page.reload()` 后仍显示"已连接到会合点：127.0.0.1:8100" + 断开按钮。
- **③ DevLogs 看不到扫码失败**：`scanOnce()` 的失败只在 UI 文案里冒泡，没写日志。
  新增 `logScanFailure()` → `addFrontendLog`（覆盖 unsupported / 插件不可用 / 权限申请 reject /
  未授权 / 未识别 五种）。验证：SPA 内导航到 DevLogs 可见 `[scan] 非原生环境，扫码不可用`。
- **❗验证方法论（踩到的假阴性）**：DevLogs 的前端日志存在**模块内存**里，
  **整页 reload 会清空** ⇒ Playwright 里用 `page.goto()` 打开 DevLogs 会看不到刚才的日志（假阴性），
  必须用 **SPA 内导航**（点 DevLogs tab）验证。
- **未稳定复现**：vitest 偶发 2 failed（连跑 4 次均 675 全绿），怀疑与后台 vite dev server
