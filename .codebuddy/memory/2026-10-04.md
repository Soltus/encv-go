## 1. `.codebuddy/skill-registry.json` 的 updatedAt 噪音 —— **源头修好**（不是靠 git hook）

- **现象**：IDE/MCP 每次扫描技能目录就把全部条目的 `updatedAt` 刷成同一时刻，
  而内容指纹 `hash`（= SKILL.md 全文 sha256）一个都没变 ⇒ `git status` 常年挂红。
- **⚠️ 我第一版做错了（用户当场指出）**：写了 `scripts/normalize-skill-registry.py` +
  `.git/hooks/pre-commit` 去"事后归一化"。用户一句"git hooks 不算真正解决方案，源头 MCP 代码
  就在当前项目" ⇒ 正确做法是**改写文件的那行代码**。
  （教训：先问"谁在写"，再谈"怎么消音"；能用源头修的，绝不上 hook / 事后补偿。
   我当初 grep 就走了弯路：codemogger 对这个 .mjs 返回空集，我没换关键字就误判"写方不在仓库内"。）
- **真源头**：`scripts/skill-manager.mjs`（app-dev MCP 用它管理技能），两处硬伤：
  ① `scanAndSync()` 里 `updatedAt: new Date().toISOString()` —— **无条件刷新**，不管 hash 有没有变；
  ② `saveRegistry()` 无条件 `writeFile` —— 内容一字不差也重写一遍，mtime 变了 git 就显示 modified。
- **修复（已落地）**：
  ① `updatedAt`：内容未变（`hash` + `path` + `displayName` + `description` 全同）⇒ **沿用 prev.updatedAt**，
     只有真变了才写当前时间；
  ② `saveRegistry()` 改为**幂等写**：序列化结果与磁盘内容相同就**不落盘**（返回 false），连 mtime 都不动。
- **验证（真实跑 MCP 代码，不是推断）**：`node` 载入 `skill-manager.mjs` 调 `loadRegistry()` + `scanAndSync()`
  ⇒ 扫到 40 个技能，registry 的 **md5 与 mtime 完全不变**（根本没写盘）。
  反向实验：临时改一个 SKILL.md（hash 变）⇒ registry md5 变 + updatedAt 刷新 ✔（真变更没被吞）；
  改回原文后再扫 ⇒ 再刷新一次（合理：内容确实又变了一次）。
- **清理**：`.git/hooks/pre-commit` 已删除（源头修好后它就是多余的"绕"）。
  `scripts/normalize-skill-registry.py` **保留**，但定位降级为：历史遗留一次性清理 + `--check` CI 校验，
  不再是解决方案本身。

## 2. Robolectric 落地：安卓 JVM 单测 36 tests / 0 failures（此前 19 failed）

- **背景**：前一天刚把 gradle 网络修通，`:app:testDebugUnitTest` 才第一次真正跑起来，
  结果是 `EncvGoServiceTest` / `GoProcessPluginTest` 全挂在

  （纯 JVM unit test 里 Android framework 只是 stub）。
- **改动**：
  - `gradle/libs.versions.toml`：`robolectric = "4.15.1"` + library 条目。
  - `app/build.gradle.kts`：`testImplementation(libs.robolectric)`；
    `android.testOptions.unitTests.isIncludeAndroidResources = true`；

  - `app/src/test/resources/robolectric.properties`：`sdk=35`、
    `robolectric.application=android.app.Application`（避开项目 Application 的 Bugly 等初始化副作用）。
- **🚨 最大的坑（不解决就是下一次"gradle 卡死"）**：Robolectric **运行时自己下载**
  `android-all-instrumented*.jar`（199MB），它**不走 Gradle 依赖解析**（Gradle 侧镜像/重试全用不上），
  默认直连 `repo1.maven.org` ⇒ 本环境恒 **429** ⇒ 7 秒就 `Failed to fetch maven artifact`。

  但 fetch 仍失败）。

  依赖 `org.robolectric:android-all-instrumented:15-robolectric-12650502-i7`，
  用 Copy task 落到 `build/robolectric-sdk`，再给 Test task 设
  `systemProperty("robolectric.offline","true")` + `robolectric.dependency.dir=<该目录>`。
  ⇒ CI/他人机器上零手工预置。
- **验证（可复现）**：特意 `mv` 走手工预置到 `~/.m2` 的 jar，再跑 —— Gradle 自动下载到
  `build/robolectric-sdk`（199MB）且 **BUILD SUCCESSFUL**。XML 报告：

## 3. 预览链路：**`:16666` 网关是沙箱专用**，非 trae 环境必须走独立 dev

- **用户纠正**：当前环境是 CNB，不是 trae 沙箱 ⇒ 不该用 `scripts/previews.sh`（preview-gateway :16666）。
- **为什么不能"直连 vite :8100"就完事**：dev 态 `getApiBaseUrl()` 的兜底是
  `DEV_SANDBOX_ENTRY = http://127.0.0.1:16666`（沙箱网关端口）。没有网关 ⇒ 所有 /api/* 打到死端口 ⇒ 断联。
  而远程访问时页面 origin 是外部域名（*.cnb.run），后端 CORS allowlist 只放行 localhost/127.0.0.1
  ⇒ 也不能让前端直连 :2025。
- **正解（已落地）**：`ENCV_STANDALONE_VITE=1 vite --port 8100`
  - `vite.config.ts`：该模式下启用 `server.proxy`（/api、/agent-api、/ping、/p、/ws(ws:true) → `BACKEND_TARGET`，
    默认 :2025，可用 `ENCV_BACKEND_URL` 覆盖）；`define` 注入 `VITE_ENCV_API_BASE=''`；
    跳过沙箱专用的 `dynamicHmrHostPlugin` 与 `remove-vite-client-sandbox-dev` ⇒ **HMR 恢复正常**。
  - `baseUrl.ts` dev 分支：优先读 `import.meta.env.VITE_ENCV_API_BASE`，存在即返回（'' = 同源）。
  - `dev-start-guard.ts`：新增 `ENCV_STANDALONE_VITE=1` 授权位（仍需显式声明，不是放开裸 vite）。
  - 沙箱链路（`SPAWN_VITE=1` / PM2）行为**完全不变**。
- **启动命令（非沙箱）**：
  ```
  ENCV_MOBILE=1 ENCV_DEV_PREVIEW=1 MOBILE_DATA_DIR=/storage/emulated/0 \
  MOBILE_DIR=/workspace/app/encv-mobile go run ./cmd/encv start      # 后端 :2025
  cd app/encv-mobile && ENCV_STANDALONE_VITE=1 vite --port 8100      # 前端（含反代）
  ```
- **验证**：`:8100/ping` 返回后端 JSON（`status:ok`）⇒ 反代通；页面 HTML 含 `@vite/client` ⇒ HMR 恢复；
  外部 `https://5osctu9yt4-8100.cnb.run/` = 200，其 `/ping` 同样返回后端 JSON。
- **回归锁（先红后绿）**：`src/api/__tests__/getApiBaseUrl.standalone.test.ts`（4 例，放 contract project
  默认跑到）：dev+override ⇒ 同源且**不是** :16666；dev 无 override ⇒ 仍走 :16666（沙箱不被误伤）。

## 4. 双端互联：手机端无信任提示 + 信任后仍连接失败（两个真因，均已修并验证）

- **复现（真实浏览器，手机视口 390×844 + 桌面视口 1440×900 同时跑）**：
  - 手机端粘贴配对码后：`sasNodeCount=0`、**信任按钮 0 个**、只有 `okMsg="已连接：<裸URL>"`
    ⇒ 桌面端在等 SAS 核对，手机端却什么都不显示（用户反馈"困惑"的来源）。
  - 手机端 `互联状态：连接中…`、桌面端 `/peers` 两个设备 `online:false`。
- **真因 A（问题 1）**：远端 Hub 的 `/api/peerlink/pair` **本来就返回 `sas`**，但
  `pairToRemoteHub()` 只解析 `peerId`/`token`，把 `sas` 丢了；`/edge/pair` 也不带
  ⇒ 手机端**拿不到**安全码，想显示也显示不了。
- **真因 B（问题 2，最关键）**：**hub 双前缀**。票据里的 `hub` **已经自带**
  `/api/peerlink` 后缀（如 `http://host/api/peerlink`），而 `startEdgeLocked()` 又拼了一次
  `hub + "/api/peerlink"` ⇒ Edge 去连 `/api/peerlink/api/peerlink/ws` ⇒ `websocket: bad handshake`
  ⇒ 手机永远"连接中…"、桌面显示离线 ⇒ 用户视角就是"信任了还是连不上"。
  - 漏网原因：既有测试 `TestPeerlinkEdgeRuntime_PairThenHubQueriesEdge` 传的 hub 是
    `srvA.URL`（**不带后缀**），与真实票据形态不同 ⇒ bug 一直没被覆盖。
  - 另一处（我自己引入）：独立 dev 的 vite 反代 `/api` 没开 `ws: true` ⇒ 连本机都 i/o timeout。
  - 还有一处放大伤害：`Edge.Start()` 把 `runSession` 的错误**吞掉**（只用于退避），
    `/edge/status` 又不返回失败原因 ⇒ UI 只能用"连接中…"掩盖失败（静默失败）。
- **修复**：
  1. `peerlink_edge_runtime.go`：`pairToRemoteHub` 返回 sas；`/edge/pair` 带 sas；
     `startEdgeLocked` 改用 `hubBaseURL(hub) + "/api/peerlink"`（归一化）。
  2. `edge.go`：新增 `LastError()/Attempts()/setLastErr()`，`Start()` 记录失败原因。
  3. `/edge/status`：返回 `lastErr` + `attempts`。
  4. `PeerScanPanel.vue`：显示 SAS 核对区 + "请在桌面端核对…" + 取消配对；
     okMsg 回显主机名（不再裸 URL）；连接失败**明文报出原因 + 常见原因提示**；
     配对后轮询状态直到连上/失败/60s。
  5. `PeerSettings.vue`：桌面端 5s 轮询在线状态（旧实现只在 onMounted 拉一次，对端掉线无感知）。
  6. `vite.config.ts`：`/api` 反代加 `ws: true`。
- **回归锁（先红后绿）**：新增 `internal/server/peerlink_edge_hub_prefix_test.go`
  —— **必须用带 `/api/peerlink` 后缀的 hub**（真实票据形态）断言：无双前缀、真连上、两端 SAS 一致。
  还原 bug 后实跑：`Edge hub 出现双前缀: "…/api/peerlink/api/peerlink"` ⇒ FAIL；恢复后 PASS。
- **验证（真实浏览器）**：两端 SAS 一致（239706 / 991910 两次均一致）、手机"已连上会合点"、
  桌面点信任后 `/peers` `online:true`、页面显示"在线"。
  Go：`./internal/peerlink` ok、`bash scripts/test-go.sh ./internal/server` OK(78s)；
  前端：vitest 675 全绿、vue-tsc 0 错误、i18n 0 缺失。
- **踩坑**：i18n 新增 key 与既有 `peers.sasTitle/sasHelp` 撞车 ⇒ TS1117 重复属性，已去重。
