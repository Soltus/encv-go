## check:all 第六次跑 + 攻克 shared typecheck（00:14）
- 用户重跑后：**Biome CI ✅PASS**（首次全绿）、encv-mobile typecheck/单测/i18n 均 PASS；仅 **shared-components typecheck FAIL（308 行）**。报告正确引用 `check-logs/shared-components-typecheck.log`，用户正查看完整日志。
- **shared typecheck 308 错根因（三层，均已修）**：
  1. **自引用解析失败**：shared 的 `tsconfig.json` 只有 `"@/*"` 映射，没有自引用 `@encv/shared-components/*`。encv-mobile 能解析是因为它 tsconfig 有 `"@encv/shared-components/*": ["../packages/shared-components/src/*"]`。shared 自己源码（`IncrementalFilter.ts`、`src/components/shared/*.vue`）引用 `@encv/shared-components/...` 全部 `Cannot find module`，但目标文件（`useFrontendLogs.ts`、`lib/workflow/types.ts`）都存在。→ 给 shared tsconfig `paths` 加 `"@encv/shared-components": ["./src"]` 与 `"@encv/shared-components/*": ["./src/*"]`。
  2. **测试文件被纳入生产 typecheck**：`include: src/**/*.ts` 把 `*.test.ts`/`__tests__/**` 收进来，它们依赖 `vitest`/`@vue/test-utils`（shared devDeps 无）→ 大片 `Cannot find module` + `implicit any`(TS7006) + `unknown`(TS2345/TS18046)。这是 308 错的大头。→ `exclude` 加 `"**/*.test.ts", "**/__tests__/**"`（标准做法：测试由 vitest 自行类型检查）。
  3. **真实类型错**：`src/composables/useEventBus.ts:13` 从 `@/api/encv` 导入 `EncvTask`，但 `EncvTask` 实际定义在 `src/types/task.ts`（其它文件都从 `@/types/task` 导入），`@/api/encv` 无此导出 → TS2305。→ 改为 `import type { EncvTask } from "@/types/task";`。
- 校验：308 错中非测试文件仅 `IncrementalFilter.ts`(自引)、`useEventBus.ts`(EncvTask)、`PhaseBadge/PhaseIcon/UnifiedTimelineCard.vue`(自引) 五处，全部被上述修复覆盖；其余全在测试文件（已排除）。预期本轮（第七次）重跑 **shared typecheck ✅ → 5/5 全绿**。
- `useEventBus.ts` read_lints 0 错。
- 注意：排除测试后 shared 的 `*.test.ts` 不再被 `vue-tsc` 类型检查（运行时仍由 vitest 跑，但 vitest 用 esbuild 不类型检查）。如需测试也类型检查，需给 shared 加 vitest/@vue/test-utils devDeps + 独立 `tsconfig.spec.json`（更大改动，留待后续）。
