# 远程调试日志：让桌面端拿到「DevLogs 同款」且在安卓端完成过滤

> 立项：2026-10-05（用户指令）
> 目标：远程调试（桌面端 → 安卓端）读取的日志，与安卓端 **DevLogs 页面看到的是同一份**；
>       并且 **等级 + 关键词过滤在安卓端做完**再回传，避免把全量日志搬到链路上。

---

## 1. 现状与差距

| 项 | 现状 | 差距 |
|---|---|---|
| Go 后端日志 | `logger.DefaultLogBuffer`（环形 500），DevLogs「后端日志」tab 与 `read_logs` **同源** | ✅ 已同源 |
| 前端（JS）日志 | `useFrontendLogs` 的模块内存（≤2000 条），**只活在 WebView 里** | ❌ 远程完全读不到 |
| 过滤参数 | `level`（单值）/ `since` / `limit`，已在执行端过滤 | ❌ 无关键词；`level` 只能单级别 |
| 传输上限 | 200 条 / 单条 2000 字符 | ✅ 保留 |

⇒ 要做的两件事：**把前端日志送到设备端 Go 进程**；**给 `read_logs` 加关键词与多级别过滤**。

## 2. 设计

### 2.1 前端日志回传本机后端（新增）

- 端点：`POST /api/logs/frontend`，body `{items:[{level,message,source?,tags?,timestamp?}]}`。
- 通道是**设备本机回环**（127.0.0.1:<后端端口>），不占跨端链路 ⇒ 与"降低通讯压力"不冲突。
- 纪律：
  1. **批量 + 节流**（≥20 条或 ≥1.5s 发一次，单批 ≤50 条），避免每条日志一个请求；
  2. **自屏蔽**：上报用原生 `fetch`，失败**静默不记日志**（否则"上报失败 → 记日志 → 再上报"递归）；
  3. 单条 message 截断 1000 字符、单批 ≤100 条（防超大 body）；
  4. 后端存进独立环形缓冲（300 条），字段与 Go 日志对齐并标 `source=frontend`。

### 2.2 `read_logs` 参数扩展

| 参数 | 语义 |
|---|---|
| `levels` | 级别列表（`["warn","error"]`），也兼容旧的 `level` 单值 |
| `keyword` | 关键词子串匹配（**大小写不敏感**），命中 message 或 source |
| `source` | `go` / `frontend` / `all`（默认 `all` = DevLogs 同款：两边都给） |
| `since` | 时间增量（沿用：只回 `timestamp > since`） |
| `limit` | 返回条数（默认 50，上限 200） |

返回：`{count, matched, returned, truncated, source, items[]}` —— `matched > returned` 调用方就知道"还有更多，可以把 since 推到本批最后一条"。

**过滤全部在执行端（安卓）完成**：调用方只拿到过滤后的结果，链路上不搬运无关日志。

### 2.3 不做的事

- 不在云端缓存设备日志（隐私 + 存储）；
- 不做全文检索（正则/模糊）——子串匹配足够排障，且正则有 ReDoS 与跨端注入面；
- 不新增脱敏规则（远程调试本来就要看真因，沿用既有 2000 字符截断）。

## 3. 验收

1. Go 单测：关键词（大小写不敏感 / 空值不误伤）、多级别、`source` 过滤、`limit` 上限、
   `matched` 与 `returned` 的语义、上报端点的条数与长度上限。
2. 前端：`addFrontendLog` 后批量上报（节流），上报失败不得再产生日志。
3. 真机：桌面端调 `read_logs{level:"error"}` 只剩 error；`{source:"frontend",keyword:"scan"}` 能命中
   安卓端 JS 日志（如 `[scan] ...`），且返回条数远小于缓冲总量。
