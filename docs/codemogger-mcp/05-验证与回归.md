## 3. 头号坑的「先红后绿」记录

**红**（`CODEMOGGER_ROOT=/workspace`，6 root 配置存在）：

```text
codemogger_list                 → No files indexed. Run `codemogger index <dir>` first.
codemogger_references useTaskStore → No imports found for: useTaskStore
codemogger_related useTaskStore    → no codebase indexed at /workspace/.codemogger/index.db
```

此时 `search`/`grep`/`leaks` 全部正常 ⇒ 极容易被误判为「这符号真的没被引用」。

**验证根因**（不靠猜）：显式重建命令被吞掉

```bash
bash codemogger-shim index /workspace --db /workspace/.codemogger/index.db
# 输出：== multi-root index (from workspace/.codemogger.json) ==   ← dir/db 被忽略
```

**绿**（把 `CODEMOGGER_ROOT` 改成已索引的 root `/workspace/app/encv-mobile`，
以及把该 root 的库拷到钉定路径后）：

```text
references useTaskStore → 5 reference(s)
related useTaskStore    → nodes=12 edges=124
```

⇒ 结论写进 03 §1：注册时必须让 `CODEMOGGER_ROOT` 落在**真实被索引的 root** 上。

## 3.1 整仓单库建成后的终态验证（2026-09-18 收尾）

`ROOT=/workspace` + 裸 CLI 建出的整仓单库（`2612 files / 21924 chunks`）之后：

| 工具 | 终态结果 |
|---|---|
| `list` | `2612 files indexed (21924 chunks)`（含 agent/combolite/encv-mobile/openlist/internal 全部） |
| `references useTaskStore` | **9** reference(s)（跨 encv-mobile + shared-components 两侧） |
| `context useTaskStore` | shared `src/stores/taskStore.ts` 8 chunk，`L37-569 <<<` |
| `impact @/api/encv` | `@/api/encv` 精确 0 条，别名变体 **287** 条 |
| `related useTaskStore` | nodes=8 / edges=145，seed 解析 10 条（含定义节点 `src/stores/taskStore.ts`） |

**「重载客户端」并不等于重拉服务进程**：改完 `/root/.codebuddy/mcp.json` 后，实测
`pgrep -f codemogger-mcp/index.mjs` 仍是 45 分钟前那个 pid，`/proc/<pid>/environ` 里
`CODEMOGGER_ROOT` 依旧是旧值 —— 客户端会复用仍在单例锁里的存活实例。
所以「改注册 → 重启」这条路径在本环境不可靠；§1.5 的「给钉定的库填上数据」才是
**不依赖进程重启**的生效方式（数据侧改变，进程不用管）。

## 5. 旧实验结论复核（哪些已经过期）

| 旧结论（仓库实验报告） | 现状 |
|---|---|
| 「keyword 不索引代码正文 / camelCase 不拆分」 | **在打过补丁的环境已不成立**：`body` 列 + 驼峰拆分生效（keyword `metadata` 命中 signature 里的 `setTaskMetadata`）。未打补丁的上游才适用 |
| 「`context useTaskStore` → ` Stores/taskStore.ts` 8 chunk，命中 L35-653（618 行）」 | **已过期**：`useTaskStore` 已迁移到 `packages/shared-components`，现在是 `L37-569`；钉 front-end 库查该符号会返回 `No context found` |
| 「`references useTaskStore` → 9 importers」 | **已过期**：迁移后实测 5 个 importer；老别名 `@/stores/taskStore` 仅剩 1 处（cypress），其余走 `@encv/shared-components/...` |
| 「`impact` 能合并 `@/` 与 `@encv/...`」 | ✅ 仍成立，且本仓库已几乎全迁到 `@encv/...`（`@/api/encv` 精确匹配 0 条） |
| 「shim 每次读前自动增量重索引」 | ⚠️ 镜像版改为**仅在库不存在时建一次**（避免多进程 WAL 竞态与慢）⇒ 新鲜度必须由调用方显式 `index` |
| 「CVE-style 陷阱：改 schema 后旧库 `no such column: body`」 | ✅ 仍需注意：patch 改 schema 时必须重索引（索引无版本/迁移机制） |
