# 06 · 索引成本与调优

> 全部数字为 2026-09-18 在 `/workspace` 实测（Node v22.23.1，磁盘 SSD 未知，CPU 6 核）。

## 1. 实测成本

| 场景 | 命令 | 实测 |
|---|---|---|
| **单库首次建**（整仓 2612 files / 21924 chunks / 114MB） | `node …/cli.mjs index /workspace --db /workspace/.codemogger/index.db` | **约 10 分钟** |
| 单库增量（**无改动**） | 同上 | **0.65s**（`skipped 2612 unchanged`） |
| 单库增量（**新增 1 个文件**，含嵌入） | 同上 | **2.5s** |
| 单库增量（**删除 1 个文件**） | 同上 | **0.78s**（`removed 1 stale`） |
| 多 root 增量（6 个 root 全无改动，经 shim） | `codemogger index`（MCP `codemogger_index`） | **1.94s** |
| 单 root FTS 检索 | `codemogger search` | 135–190 ms / root |

⇒ **结论：索引更新机制是合理的**（内容 hash 增量，不是 mtime；新增/修改/删除三种变化都能被感知）。
冷启动那 10 分钟是一次性成本（CI 里已用后台 `nohup` 承担），日常刷新是亚秒级。

## 2. 索引构成（整仓单库 2612 个文件）

| 分区 | 文件数 | 占比 |
|---|---|---|
| `app/` 全部 | 1872 | 72% |
| └ 其中**自有代码**（encv-mobile + shared-components + preview-gateway + scripts…） | **766** | 29% |
| └ 其中 **vendored fork**（`app/openlist/*` 705+219、`app/combolite` 157） | ~1106 | 42% |
| `internal`（Go 后端）+ `agent` + 根目录脚本等 | ~740 | 28% |

也就是说：**整仓单库里约 70% 的条目对「前端↔shared 引用图」没有价值**（第三方 fork、Go 后端、
59 个已构建的前端 bundle 资源 `/assets/*.js`）。

副作用：跨仓库单库会把同名符号混进一张图（Go 的 `Manager`/`Config` 与前端的同名符号），
`references`/`related` 里可能出现跨仓库噪声 —— 可用 `related` 输出的 `[noise]` 标记与
typed edge 判别，也可用下面的裁剪方案降低。

## 3. codemogger 的忽略机制（源码级事实，决定你能怎么裁）

`scanDirectory()`（`dist/cli.mjs`）：

| 规则 | 实现 |
|---|---|
| 忽略文件来源 | **只读 `<rootDir>/.gitignore`**（**不读嵌套的**子目录 .gitignore，所以 `app/openlist/.gitignore` 无效） |
| 匹配方式 | `ignorePatterns.has(name)` ⇒ **按 basename 匹配**，不是 glob/路径 |
| 通配符 | `loadIgnorePatterns` 直接丢弃**含 `*` 的行** ⇒ `*.log` 这类写法无效 |
| 硬编码忽略 | `ALWAYS_IGNORE = {.git, node_modules, target, build, dist, .next, __pycache__, .tox, .venv, venv, .mypy_cache, .cargo, .rustup}` |
| 其它跳过 | 名称以 `.` 开头的目录/文件、空文件（size 0）、>1MB 文件、符号链接、非已配置扩展名 |
| 语言过滤 | `scanDirectory(rootDir, languages)` 支持按语言过滤，但 CLI 未把该参数暴露到 MCP |

⇒ **可行裁剪手段只有一条**：往**根** `.gitignore` 里加**不带通配符的 basename 行**。

## 4. 优化选项（按推荐度）

### A. 维持现状（当前采用，推荐）

- 冷启 10 分钟一次（CI 后台跑），之后**亚秒级增量**。
- 换来跨仓库完整引用图（`references useTaskStore` 9 条 vs 单前端库 5 条）。
- 噪声可控：`search` 走的是各 root 自己的库（不受单库噪声影响）；
  `references`/`related` 的跨仓库同名符号用 `[noise]` 与边类型判别。

### B. 把 ROOT 收窄到 `/workspace/app`

- 索引量 1872 files（**−28%**），丢掉 `internal`/`agent`（Go 后端不进引用图）。
- 前端↔shared 的跨包图**完整保留**。
- 代价：改注册 `CODEMOGGER_ROOT=/workspace/app` + **重拉服务进程**（改注册本身不生效，见 05 §3.1），
  并重建单库（约 7 分钟）。

### C. 排除 vendored fork（收益最大）

在**根 `.gitignore`** 追加（basename、无通配符）：

```gitignore
# codemogger 单库裁剪：这些是本地 clone 的第三方 fork，已有独立 root 供 search 使用
Hi-Sillot-OpenList
Hi-Sillot-OpenList-Frontend
ComboLite
```

- 索引量降到 **~790 files（−70%）**，冷建约 3 分钟。
- 对 `codemogger_search` **无影响**（它读各 root 自己的库，fork 仍有独立 root）。
- 代价：改动仓库根 `.gitignore` 的语义（这几个目录本就未被 git 跟踪，影响很小）；
  且它同样会让 `git status` 少显示这些目录 —— 属可接受但需团队知情。

### D. 镜像侧改进（**建议镜像项目做**，治本）

1. **shim 增加单库逃生开关**：`--single-root` / `CODEMOGGER_SINGLE_ROOT=1`，
   让 `index <dir> --db <path>` 在存在 `.codemogger.json` 时也能按传入参数执行，
   从而让 MCP `codemogger_index` 能直接建/刷新钉定的单库（现在必须裸调 CLI）。
2. **`register.mjs` 智能选 ROOT**：存在 `.codemogger.json` 时，默认把 `CODEMOGGER_ROOT`
   设为 weight 最高的 root（当前硬编码 `/workspace`）。
3. **暴露 `languages` 过滤**：`scanDirectory` 已支持按语言过滤但 CLI 未暴露，
   暴露后可按 `--languages ts,tsx,vue,kt,go` 裁剪索引。
4. **读取嵌套 .gitignore**（或支持 `.codemoggerignore`）：当前只读根目录的，
   导致 fork 自带的忽略规则失效。

## 5. 排障速查

| 现象 | 原因 / 处理 |
|---|---|
| `Error: database is locked` | 有 `index` 进程正在写同一个库，等它结束（读请求不要在写库时发） |
| `No files indexed` | 钉定的库是空的；见 03 §1 |
| `no codebase indexed at …` | 同上（`related` 的提示更明确）；另外**孤立的 `-wal`/`-tshm` 旁文件**也会让 libSQL 读成空库 |
| 索引体积暴涨 | 检查是否被 vendored fork / 构建产物混入，用 §4 C 裁剪 |
| 改了代码查不到 | 显式刷新（单库用裸 CLI；各 root 库用 MCP `codemogger_index`），shim 默认不自动重索引 |
