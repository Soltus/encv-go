# 02 · 工具参考（10 个）

调用方式统一：`mcp_call_tool(serverName:"codemogger", toolName:"<名>", arguments:{...})`。

参数名写错不会被静默忽略：系统会拒绝并提示 `Valid parameters for '<tool>': …`
（`pattern` / `q` / `text` / `term` 都是 `query` 的别名，但仍建议写规范名）。

## 依赖模型的两张表

| 类别 | 工具 | 数据源 |
|---|---|---|
| **单 root**（钉 `CODEMOGGER_ROOT/.codemogger/index.db`） | `list` `references` `context` `impact` `related` | 单个 SQLite（libSQL）库 |
| **多 root**（读 `.codemogger.json`） | `index` `search` `grep` | 各 root 自己的库 + grep 补集 |
| **与库无关** | `leaks`（纯 grep）、`css_source`（读 `*.css.map`） | 文件系统 |

---

## 1. `codemogger_list`

列出已索引 codebase（**单 root**范围）。
参数：无。

```text
No files indexed. Run `codemogger index <dir>` first.      ← 钉的库是空的
489 files indexed (3909 chunks): …                          ← 有数据
```

> 只反映**当前 `CODEMOGGER_ROOT` 指向的库**，不代表多 root 各库的状态（后者可能都已就绪）。

## 2. `codemogger_index`

多 root 重索引：遍历 `.codemogger.json` 的 `roots`，各建 `<root>/.codemogger/index.db`。
参数：`dir`（可选，默认 `CODEMOGGER_ROOT`）。

- 实测：6 个 root 全量索引耗时约 **8–12 分钟**（前端 13.3MB / Go 后端 29.9MB / OpenList 32MB 量级）。
- **显式 `dir` 在有 `.codemogger.json` 时会被忽略**（见 03 §1.3）。
- MCP 请求有超时上限，超大仓库建议拆步验证：跑 `index` 后立刻 `list` 看是否成形。

## 3. `codemogger_search` ⭐ 跨仓库发现

多 root **混合**检索：每个 root 跑一次 CLI 自带检索（默认 **semantic**，limit=5），再跑该 root 的
**grep 补集**（文档/配置/CLI 解析不了的文件）。结果按 root weight 降序、每块带 `---- [root · w=…] ----` 标签。

参数：`query`（必填）、`dir`（限定 grep 补集子树）、`format`（`text` | `json`）。

**概念感知**：命中 `concepts` 键时，把该概念展开成一组精确词再做 per-root grep（避免裸 `SPA`
匹配到 `xcworkspace` 这类子串噪声）。

```jsonc
// 实测：query="taskTypeLabel"
// shared-components(w=1) FTS: getTaskTypeLabel / getTaskTypeMeta / MICROSERVICE_METHOD_LABELS …
// encv-mobile(w=1)      FTS: TestItem / EncvTaskCancelWorker(Kotlin!) / ReasoningEffort …
// internal(w=0.9)       FTS: TaskIndexItem / TaskExtraFieldsSetter(Go)
// openlist(w=0.8)       FTS: getTaskInfos / Manager(Go)
// combolite(w=0.7)      FTS: LaunchMode(enum class) / ConvertAarToApkTask(Kotlin)
// preview-gateway(w=0.6)FTS: ViteDenyRule / *Manager.Status(Go)
// + 每 root 的 grep 补集（文档/.vue/.ts 里的调用点）
```

> ⚠️ 输出可能很大（概念查询实测单次返回 ~250 条）。需要机器处理时用 `format:"json"`。
> ⚠️ 默认 semantic + `limit=5`（CLI 默认），**MCP 层没有暴露 `limit`/`mode`**，想精确定位定义请用
> `references` 或 `-mode keyword` 的裸 CLI（见 03 §3）。

## 4. `codemogger_grep`

对 `.codemogger.json` `grep.include` 集合做**（固定串）grep**——覆盖 Go/文档/配置/样式等
CLI 的 FTS 索引不到的「通用知识」。

参数：`query`（支持 `|` 作 OR）、`dir`（限定单目录）、`format`。

```jsonc
// { "query":"build-theme-scss", "dir":"/workspace/app/packages/shared-components" }
[
  {"file":"…/package.json","line":8,"match":"    \"build:scss\": \"node scripts/build-theme-scss.mjs\""},
  {"file":"…/src/theme/THEME_DEV.md","line":944,"match":"- **可溯源产物生成器**：…"}
]
```

## 5. `codemogger_references` ⭐ 影响面

谁 import 了它。**单 root**。
参数：`target`（必填）、`mode`（`symbol` 默认 | `module` | `file`）、`format`。

| mode | 含义 |
|---|---|
| `symbol` | 别名无关的「爆炸半径」：谁 import 了这个符号 |
| `module` | 按模块说明符**精确**匹配（`@/x` 与 `@encv/shared-components/x` 是两行） |
| `file` | 列出该文件自身的依赖（相对路径由 shim 自动转绝对） |

```text
// 实测 references useTaskStore（root=app/encv-mobile）
5 reference(s) for "useTaskStore":
  cypress/support/store-helpers.ts                    imports useTaskStore  <-  @/stores/taskStore
  …/buildDynamicWorkflow.pre-population.test.ts        imports useTaskStore  <-  @encv/shared-components/stores/taskStore
  …/buildDynamicWorkflow.real-e2e.test.ts              （同上）
  __tests__/fixtures/TaskListDiagSimulator.tsx         （同上）
  src/stores/registerSharedTaskServices.ts             （同上）
```

坑见 [03 §4](./03-能力边界与已知坑.md)：库为空时返回 `No imports found for: X`
（听起来像「没人引用」，其实是「没索引」）。

## 6. `codemogger_context`

符号所在**整文件**的 chunk 大纲（命中处标 `<<<`），或某文件路径的大纲。**单 root**。
参数：`target`（符号名或文件路径，文件路径支持后缀 LIKE）、`expand`（打印每个 chunk 正文）。

```text
// 实测 context useTaskStore（钉 shared-components 库）
/workspace/app/packages/shared-components/src/stores/taskStore.ts  (8 chunk(s))
  L26-26  [type] ViewMode
  …
  L37-569  [variable] useTaskStore  <<<

// 实测 context src/stores/registerSharedTaskServices.ts（钉 encv-mobile 库）
…/registerSharedTaskServices.ts  (2 chunk(s))
  L29-29  [variable] registered  <<<
  L32-61  [function] registerSharedTaskServices  <<<
```

注意：`useTaskStore` 的定义已迁入 shared 包，钉 front-end 库时 `context useTaskStore` 会返回
`No context found`（数据正确，不是工具坏了）——同一符号按实体所在位置选库。

## 7. `codemogger_impact` ⭐ 重构前必跑

别名无关的波及面：同时查 `@/x` 与 `@encv/shared-components/x` 并合并 importer 列表。**单 root**。
参数：`target`（模块别名或裸符号）。

```text
// 实测 impact @/api/encv
== importers of module '@/api/encv' (exact) ==
No imports found for: @/api/encv                    ← 老别名已全部迁走
== importers of module '@encv/shared-components/api/encv' (alias variant) ==
132 reference(s) for "@encv/shared-components/api/encv"
```

## 8. `codemogger_leaks`

列出某目录下 shared→app 的**反向 `@/` import**，验证「shared 层不依赖 app 层」不变量。
**纯 grep，不依赖任何索引库**——这是它在空库环境下依然可信的原因。参数：`dir`。

```text
// 实测 leaks /workspace/app/packages/shared-components/src
…/src/api/encv_perf.ts:7:// 此处 re-export 以兼容现有 `import ... from '@/api/encv_perf'`。
…/src/api/encv_tasks.ts:16:// 下方 re-export 以兼容现有 `import ... from '@/api/encv_tasks'` / `'@/api/encv'`。
```

> 输出未区分注释与真实 import：实测这两条都是**注释**，需人工判断（或改用 `grep` 复核）。

## 9. `codemogger_related` ⭐ 多跳关联图

给一个种子（符号 / 模块 / 文件 / 需求文本），走三类关系并做**带权重、带类型、按跳数衰减**的
noisy-OR 传播：（实测相关 detail 见 03 §6）

- `explicit`：`imports` / `imported-by` / `defines`
- `crossLayer`：跨层也有域 token 相同（route→service→repo→db 一跳穿透）
- `hidden`：从不相干但引用同一个具体 token（配置键 / 常量 / 事件名）的两个文件建立关联
  （自构倒排表，**不是** embedding 相似度）

参数：`seed`（必填）、`depth`(3, ≤4)、`maxNodes`(200)、`direction`(both/upstream/downstream)、
`include`([explicit,hidden,crossLayer])、`weights`（覆写 import/define/crossLayer/hiddenConfig/hiddenConst/depthDecay/minScore）、
`threshold`(0.05)、`format`。

```text
// 实测 related useTaskStore depth=3 maxNodes=12
nodes=12 edges=124
seed resolution (5): store-helpers.ts / buildDynamicWorkflow.*.test.ts / TaskListDiagSimulator.tsx / registerSharedTaskServices.ts
typed edges:  imports: 79 | imported-by: 30 | defines: 15
```

## 10. `codemogger_css_source`

编译后 CSS → SCSS 源溯源（解 `*.css.map` 的 base64-VLQ，零依赖）。
参数：`file`（`.css` 产物，须有同目录 `.css.map`）、`line`（单行溯源）、`format`、`top`（汇总条数）。

```text
// 实测 css_source …/src/theme/.dist/vivid.css
generated lines: 94  |  mapped SCSS sources: 2
   68.1%  64 lines  …/theme/vivid.scss       sample: css:2 → scss:1:1
   22.3%  21 lines  …/theme/_vivid-p3.scss   sample: css:17 → scss:1:1
```

前提：产物必须带 map。生产 Vite 不产出时用专用脚本生成可溯源产物
（本项目：`pnpm build:scss` → `src/theme/.dist/{surface,vivid}.css{,.map}`，实测可用）。
