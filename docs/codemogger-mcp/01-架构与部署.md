# 01 · 架构与部署

## 1. 目录结构（镜像落位 `/scripts/codemogger-mcp/`）

```
codemogger-mcp/
├── index.mjs               # 入口：装配工具 + stdio JSON-RPC + 接管式单例锁
├── register.mjs            # 合并注册进 /root/.codebuddy/mcp.json（构建时执行）
├── codemogger-shim         # bash shim：自动建库 + 三大 UX 坑缓解 + impact/leaks/related 辅助命令
├── apply.sh                # 幂等安装器：装 Kotlin wasm + 打补丁 + 覆盖 codemogger bin
├── force-wasm-grammars.mjs # 把 tree-sitter-typescript 改成 WASM-only（arm64 构建修复）
├── css-source.mjs          # CSS 产物 → SCSS 源溯源（被 shim 调用）
├── patches/                # cli.mjs 补丁（0.1.5 源码基线）
│   ├── codemogger+0.1.5.patch             # Kotlin + Vue + 全文检索 + references + imports 表
│   ├── codemogger+0.1.5+context.patch     # context 命令（须在主补丁之后应用）
│   └── codemogger+0.1.5+stale-imports.patch
├── vendor/tree-sitter-kotlin/             # 只保留 .wasm（prebuilds/src 已裁剪）
├── lib/
│   ├── config.mjs          # ROOT / SHIM / DB / NO_AUTOINDEX，路径全部由本文件位置推导
│   ├── shim.mjs            # runShim（默认带 --db 钉库）+ parseHits / parseSearch
│   ├── args.mjs            # 别名归一 + 未知参数拒绝（did you mean?）
│   └── util.mjs            # textResult / trim / MAX_OUT
└── tools/                  # 每个 MCP 工具一个文件
    ├── codemogger_{references,context,search,grep,impact,leaks,index,list,css_source,related}.mjs
```

## 2. 运行时链路

```text
MCP 客户端
   │ stdio JSON-RPC
   ▼
index.mjs ──(dispatch: 别名归一 + 未知参数拒绝)──► tools/*.mjs handler
                                                     │
                                                     ├─► bash codemogger-shim <subcmd> … --db <DB>
                                                     │        └─► node <global>/codemogger/dist/cli.mjs
                                                     │               └─► SQLite(libSQL) + onnx 嵌入模型
                                                     └─► codemogger_related 例外：直接用 libSQL 读 chunks/imports 表
```

- `runShim` 默认追加 `--db <DB>`，只有 `search` / `grep` / `index` / `list` 走 `{ db: false }`
  （多 root 或不需要库的场景）。
- `related` 不经过 shim，直接 `createRequire(join(CODEMOGGER_DIR,"dist","cli.mjs")).resolve` 取
  `@tursodatabase/database` 的 `connect`，连接 `DB`（选项 `experimental:["index_method","multiprocess_wal"]`，
  失败降级为无选项连接）。

## 3. 环境变量（`lib/config.mjs`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `CODEMOGGER_ROOT` | `/workspace` | 单 root 根；`DB = <ROOT>/.codemogger/index.db`，也是 `references/context/impact/leaks/list/related` 钉的库 |
| `CODEMOGGER_SHIM` | `<SERVER_DIR>/codemogger-shim` | shim 路径 |
| `CODEMOGGER_AUTOINDEX` | `1` → 关 | 设为 `1` 才让 shim 在读命令前自动索引 |
| `CODEMOGGER_CONFIG` | `/workspace/.codemogger.json` | 多 root / 概念词表 / grep 规则 |
| `CODEMOGGER_GREP_ROOT` | 含配置的工作区目录 | `grep` / `search` 的 grep 补集根目录（MCP 里由 `dir` 参数注入） |
| `CODEMOGGER_DIR` | `/usr/local/lib/node_modules/codemogger` | 全局 CLI 安装位置（server patch/vendor 与 `related` 的 require 基准） |

> 所有 MAGIC PATH 都**由文件自身位置推导**（`import.meta.url`），因此 `COPY scripts /scripts`
> 无论落到绝对 `/scripts` 还是相对 `./scripts` 都成立，代码里禁止硬编码 `/scripts`。

## 4. 部署顺序（Dockerfile）

```dockerfile
# 1) 安装 CLI 本体（必须在就校本环境切断 node-gyp 链，见下）
RUN npm install -g --ignore-scripts codemogger@0.1.5
# 2) 打补丁 + 装 Kotlin wasm + 覆盖 codemogger bin
RUN bash /scripts/codemogger-mcp/apply.sh
# 3) 合并注册进用户级 MCP 配置
RUN node /scripts/codemogger-mcp/register.mjs
```

### arm64 构建坑（已修）

`tree-sitter-typescript` 的入口是 `bindings/node`（`node-gyp-build`），会在 install 阶段触发源码编译。
arm64 下 `node-addon-api` 被 npm hoist 出包，`binding.gyp` 里
`<!(node -p "require('node-addon-api').targets")` 解析出带 `..` 的路径，gyp 生成的 Makefile include 了
build 树之外的 `.target.mk` → `make: *** No rule to make target '.../node_addon_api_except.stamp'`。

`force-wasm-grammars.mjs` 把入口改写成纯 JS 的 `wasm-only.cjs`。
**不损失能力**：codemogger 的 `cli.mjs` 本来就只用 web-tree-sitter 的 `Language.load(wasmPath)`，
从不 require 原生绑定（TS/TSX/Vue/Kotlin 实测正常）。

自检：`node /scripts/codemogger-mcp/tests/wasm-grammars.test.mjs /usr/local/lib/node_modules`

## 5. 进程治理

- **接管式单例锁** `/tmp/codemogger-mcp.lock`：新实例先用 `/proc/<pid>/cmdline` 验证持有者确实是
  本 server（同 `index.mjs`/`codemogger-mcp.mjs` 且 cwd 可解析到同一绝对路径），确认后才 `SIGTERM`/`SIGKILL`
  并夺锁，保证客户端重启永远成功而不会撞上一具僵尸。
- **stdin 关闭不强制 exit**：可能仍有 `index` / 慢 `search` 在飞，强制退出会截断响应；
  改为让事件循环自然排空，Node 自行退出时由 `exit` 钩子放锁（配合上面的夺锁，不会泄漏孤儿）。

## 6. 注册：`register.mjs`

- 目标是 `/root/.codebuddy/mcp.json`，**merge 不是覆盖**：已有 `mcpServers` 条目保留。
- 写前 JSON round-trip 校验 + 临时文件 + `rename` 原子落盘；原文件损坏则备份为
  `mcp.json.corrupt-<ts>.bak` 而非静默丢弃。
- 默认 ENTRY：

```json
{
  "command": "node",
  "args": ["/scripts/codemogger-mcp/index.mjs"],
  "env": { "CODEMOGGER_ROOT": "/workspace" }
}
```

> ⚠️ 若业务仓库有自己的 `.codemogger.json` 多 root 配置，`ROOT=/workspace` 会让
> **单 root 工具读到永远建不出来的库**（`index` 走多 root 循环）。注册时应把
> `CODEMOGGER_ROOT` 指向**某个真实被索引的 root**（本项目用 `/workspace/app/encv-mobile`）。
> 详见 [03 §1](./03-能力边界与已知坑.md)。

## 7. 与 `cmd-run` MCP 的关系

参照同一个 MCP 家族：同样 `lib/` + `tools/` + `index.mjs` + `register.mjs` 结构。
差异只有一点：codemogger 是**只读检索**，因此不带安全门禁与 Web 审批门户。
两者正交——本服务替换的是「平台内置检索」，不替换「终端命令执行（cmd-run）」。
