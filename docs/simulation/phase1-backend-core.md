# Phase 1 Spec — 纯后端核心引擎

> **阶段目标**：搭建 SimVerse 世界引擎的纯后端核心，验证规模可行性与性能基线
> **状态**：v0.1 — 规划中
> **前置依赖**：无（第一阶段）
> **后续阶段**：Phase 2（前后端联通）

---

## 一、阶段目标

本阶段只做后端，不涉及前端。目标是：

1. ✅ **验证规模可行性**：10M NPC + 1M 组织 + 分形格系统，Android 平均内存 <100MB
2. ✅ **建立性能基线**：catch-up 速度、事件吞吐量、内存占用
3. ✅ **核心架构落地**：分形嵌套 + 统计分布代理 + 三层性能调度
4. ✅ **可独立测试**：所有功能通过 Go test / Go benchmark 验证

## 三、性能指标（本阶段必须达成）

### 3.1 内存指标（Android 目标）

| 项目 | 目标值 | 当前状态 |
|------|--------|---------|
| 热 NPC 缓存 (10K) | < 2 MB | ✅ ~1.8 MB |
| 核心格缓存 (160万) | < 80 MB | ⚠️ ~77 MB (需压缩优化) |
| 数据库缓存 | < 20 MB | 待验证 |
| 运行时 + 代码 | < 20 MB | 待验证 |
| **总计** | **< 100 MB** | **~140 MB (需 Phase 3 优化)** |

### 3.2 CPU 指标

| 操作 | 目标 | 验证方式 |
|------|------|---------|
| NPC Catch-up | < 0.1 ns/NPC/tick | Benchmark |
| 每日世界推进 (10K NPC) | < 5 秒 | 集成测试 |
| 事件调度吞吐 | > 10K events/s | Benchmark |
| 前台 tick 间隔 | < 16 ms (60fps 预算内) | 集成测试 |

### 3.3 规模指标

| 维度 | 目标 | 验证方式 |
|------|------|---------|
| NPC 总数 | 10M | 统计分布代理验证 |
| 组织总数 | 1M | 统计分布代理验证 |
| 核心格总数 | 10M 级 | 玩家焦点辐射模型验证 |
| 脑区数量 | 8 个 | 格系统验证 |
| 分形层级 | 3 层可扩展 | 架构验证 |

## 五、验收标准

1. ✅ 所有单元测试通过（`go test ./internal/simverse/`）
2. ✅ 性能基准测试达标
3. ✅ 3 分钟长稳测试无内存泄漏
4. ✅ 内存估算 < 200 MB（优化目标 100MB）
5. ✅ 分形架构可扩展验证
6. ⬜ 可在 Android 真机上运行（需 Phase 2 集成后验证）

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 格系统内存超标 | 中 | 高 | Phase 3 压缩优化 + 分层加载 |
| Catch-up 复杂度失控 | 低 | 高 | 保持算法纯算术，禁止复杂循环 |
| 数据库性能瓶颈 | 中 | 中 | ObjectBox 热数据 + SQLite 冷数据分层 |
| 分形层级间耦合过深 | 低 | 中 | 严格自相似设计，统一接口 |
