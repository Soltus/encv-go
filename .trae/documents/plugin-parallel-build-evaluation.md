# 插件构建：现状保持

## 结论

**不改动。** 当前 1 个插件的硬编码方式完全足够。

## 原因

| 维度 | 分析 |
|------|------|
| 当前插件数 | 1 个（MPV player） |
| 硬编码位置 | ~6 处，全部在同一个文件 [android.yml](file:///workspace/.github/workflows/android.yml) |
| 改变量名的实际收益 | 零 — 仍需手动复制整块步骤，只是把 `mpv-player` 换成 `${VAR}` |
| 可读性 | 变量化后反而下降（要跳转查变量定义才知道实际值） |
| GitHub Actions 限制 | `name:` 不支持变量；`env:` 多插件会命名冲突 |

## 未来触发条件

当添加 **第 2 个插件** 时，再根据两个插件的实际情况决定是否抽取公共逻辑。届时：
- 需求更清晰（知道两个插件的异同点）
- 重构目标明确（消除的实际重复代码）
- 可以一次性设计正确的抽象
